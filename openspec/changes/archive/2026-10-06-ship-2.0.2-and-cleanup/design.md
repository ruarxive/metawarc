## Context
The 2026-09-17 review (`PRODUCT_REVIEW_AND_IMPROVEMENT_PLAN.md`) closed every
P0–P2 finding from the 2026-08-04 review. The 2.0.2 changelog entry was
prepared on 2026-09-18 (commit `8ed99f5`), but no release tag, no PyPI
artifact, and no built `dist/` snapshot for 2.0.2 was created at the same
time. `git describe --tags` therefore reports `v2.0.1-12-gb272283` and
the existing `dist/metawarc-2.0.1-*` artifacts are still in the working
tree. A contributor who runs `pip install metawarc` from a built artifact
today receives 2.0.1; `pip install metawarc==2.0.2` from a registered tag
would currently fail.

Two open Dependabot PRs (#34 pyjwt 2.15.0, #35 urllib3 2.8.0) fix 100 % of
the 17 known CVEs reported by `pip-audit` in the dev install. The
`test` CI job does not currently run `pip-audit`; only the `package` job
does. Contributor environments therefore run with the vulnerable
transitive versions despite the package job's clean bill of health.

An orphan `v2` branch at `94db570` (older than the `v2.0.0` tag) sits
alongside `origin/master` and the preserved `testing` line. It is not
referenced from `README.md`, `CHANGELOG.md`, or the docs site, and a
first-time contributor could mistake it for the canonical 2.x line.

The root `.gitignore` lists `.coverage.*` (line 50) but not the literal
`.coverage` filename, so the file generated by a contributor's first
`pytest --cov` run appears as an untracked file.

`pyproject.toml` `[project.optional-dependencies].dev` requires
`httpx2>=2.12`. `httpx2` is a PyPI mirror of `httpx` that starlette 1.x
imports internally as `httpx` (`starlette/testclient.py` does
`import httpx2 as httpx`). The mirror is therefore required for
`fastapi.testclient.TestClient` to load. The `>=2.12` pin keeps the
closure off the vulnerable 2.9.1 release.

## Goals / Non-Goals

- Goals:
  - produce a `v2.0.2` Git tag, PyPI artifact, and GitHub release from
    commit `b272283` (or the equivalent tip) so tag, changelog, version
    metadata, and artifacts agree;
  - clear all 17 known CVEs in the dev install via the existing
    Dependabot PRs;
  - remove or rename the orphan `v2` branch and document the result;
  - close the `.gitignore` gap for `.coverage`;
  - replace `httpx2` with `httpx` in the dev extras.
- Non-Goals:
  - any user-visible CLI/API/MCP behavior change;
  - reissuing or moving the existing `v2.0.0` and `v2.0.1` tags
    (the `release-engineering` requirement "Immutable release history"
    forbids this);
  - introducing a new release process or a new dependency manager.

## Decisions

### Decision: Tag and publish from the current `master` tip

`master` is at `b272283` after the macOS CI addition. The commit
`8ed99f5 chore: prepare 2.0.2 and clean dependency hygiene` already
contains the changelog and `pyproject.toml` updates. The 12 commits
between `v2.0.1` and `b272283` are macOS CI, MCP test hardening, and
OpenSpec archiving — none change user-visible behavior. Tagging at the
current tip therefore satisfies the `release-engineering` requirement
"Canonical release source" without requiring a code-level reconciliation.

### Decision: Use Dependabot PRs instead of in-repo bumps

The two open PRs (#34, #35) already target the resolved versions and have
passed CI. Merging them is faster, lower risk, and auditable through the
PR history. An in-repo bump would duplicate Dependabot's work and
introduce a maintenance fork.

### Decision: Delete the `v2` branch with confirmation

`94db570` predates `v2.0.0` (tagged at `dd20c27`). It is not the head of
any published branch other than the local `v2` ref. The `release-engineering`
requirement "Immutable release history" applies to tags, not to ad-hoc
branches. After confirming via `git branch -r --contains 94db570` that no
fork or clone depends on the branch, delete it. If any fork does, rename
to `archive/pre-2.0-line` so the intent is obvious.

### Decision: Keep `httpx2` with the >=2.12 pin

`httpx2` is a PyPI mirror of `httpx` that starlette 1.x imports
internally as `httpx` (`starlette/testclient.py` does
`import httpx2 as httpx`). The mirror is therefore required for
`fastapi.testclient.TestClient` to load. The fix versions for the six
httpx2 CVEs (2.10.0–2.12.0) are already in the mirror's history, and
the current `>=2.12` pin keeps the closure off the vulnerable 2.9.1
release. A future upgrade to a starlette version that supports plain
`httpx` would remove the mirror entirely, but that is outside the
scope of this change.

## Risks / Trade-offs

- Publishing to PyPI is one-way → Mitigation: build and smoke-test
  in CI before publishing; rely on the existing `metawarc` package's
  sandboxed environments; keep the `v2.0.1` tag immutable per spec.
- Deleting `v2` could break a downstream clone that happens to be on
  that ref → Mitigation: confirm no fork depends on it; otherwise
  rename.
- Removing `httpx2` could break a contributor who has vendored it
  → Mitigation: the change is scoped to the `dev` extra; runtime
  installs are unaffected.

## Migration Plan

1. Land this change through the standard PR flow on `master`.
2. Run the verification harness in §5 of `tasks.md`.
3. Tag and publish from the merge commit (the tag-commit must equal the
   merge-commit per `release-engineering` "Artifact provenance").
4. Merge Dependabot PRs #34 and #35 as part of the same release PR or
   in fast-follow PRs that target the same release commit.
5. Delete `v2` from `origin` (or rename) after the verification step
   confirms no fork depends on it.

## Open Questions

- Should the tag be created before or after the Dependabot merges? If
  before, the wheel/sdist will carry the pre-fix dependency closure; if
  after, the wheel/sdist will reflect the post-fix closure. Recommendation:
  after, so the published artifact matches the developer-visible install.
- Is the macOS CI addition (`b272283`) a user-visible change worth
  mentioning in the changelog? Recommendation: yes, as a single line in
  the 2.0.2 entry under "Changed".
